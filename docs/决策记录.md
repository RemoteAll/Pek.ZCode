## 2026-11-11 第一轮实现：Zig ORM 核心链路（基于 DH.NCode / Pek.RCode）

- **用户原话**：「`G:\Code\Pek.FrameWork\DH.NCode` 我要参考这个项目实现数据库ORM功能，功能语义和逻辑需要一模一样，`G:\Code\Rust\Pek.RCode` 这个是Rust版本的同样来自于DH.NCode。现在你要基于这两个项目来实现ZigLang语言的数据库操作ORM库.」
- **用户当时不可用**（提问工具返回「not available」），按「可回退、可继续」原则自主定档，均记录在此便于后续推翻：
  1. 首批驱动 **仅 SQLite**（与 C# 默认库、Rust 默认链路一致；MySQL 等网络库留后续轮次）；
  2. SQLite 接入 **动态加载 DLL**（`sqlite3.dll` → `winsqlite3.dll`），不链 libc / UCRT（Win7 可随包附带）；
  3. 首轮范围 = **核心链路**：`Model.xml` + 类型/值 + 方言 + SQL 组装 + 条件/分页 + 会话 + 表级 CRUD + 连接串 + 增量建表；
     对象实体/脏更新/缓存/批量写/分表/其它驱动留后续。
- **事实基线（实测，非推测）**：
  - `DH.NCode`：核心 `DH.NCode/Entity/Entity.cs` 99,615 B、`DataAccessLayer/DAL.cs` 33,388 B，另有 11 个数据库驱动工程；
  - `Pek.RCode`：`src/` 下 50+ 模块、约 3.4 万行 Rust（`dal.rs` 4,866 / `dialect.rs` 2,354 / `entity.rs` 1,838 等），README 记录 309 项测试；
  - `zzig` 在 Zig 0.17 下 `zig build` 通过（exit 0）→ 其 `xml` DOM 可作为 `Model.xml` 解析的复用基础（未自研 XML 解析器）。
- **落地实现**（`src/`，共 12 个模块 + 集成测试）：
  `types` / `decimal` / `datetime` / `value` / `buf` / `model` / `dialect` / `query` / `sqlbuild` / `session` / `sqlite` / `dbtable` / `dal` / `tempfile`。
  - 方言黄金断言**直接移植自 Rust 版单测**（引用符/占位符、SQLite 类型映射、SQLite 建表约定、索引缺省名、
    MySQL longtext 索引前缀、分页语法、删列/删索引/删表文本）——保证生成 SQL 文本逐字可对照；
  - `sync_schema` 幂等（二次同步 0 变更）与「新增列自动补齐」由集成测试固化；
  - 全部差异与未实现项写入 `docs/移植对照-NCode.md`（含「有意为之的差异」一节）。
- **Zig 0.17 实测坑（本轮踩到并修，已写入对照文档第 4 节）**：
  1. `std.DynLib` **不支持 Windows** → 手写 `LoadLibraryA/GetProcAddress`；
  2. `std.time.timestamp`/`nanoTimestamp`、`std.crypto.random`、`std.fs.cwd`/`selfExeDirPathAlloc`、`Allocator.dupeZ` 全部移除；
  3. `ArenaAllocator` 中途复制会漏掉后续分配（模型解析一度泄漏）；
  4. `sqlite3_bind_text` 用 `SQLITE_STATIC` + 栈缓冲 → 读到已失效内存（`"12.3400"` 变 `"400"`），改 `SQLITE_TRANSIENT`；
  5. 连接串 `Data Source` 借用入参切片 → `Dal` 持有了悬垂切片，生成 `UUUU...` 垃圾库文件，改为自持复制。
