# 代码生成（zcodegen）：Model.xml → 可直接使用的 Zig 实体

生成器 `tools/zcodegen.zig` 与 C# XCode 的 `XCodeTool` 同定位：**实体不手写**。
手写实体没有脏位图，`update` 会写全部非主键列（写放大、并发下丢增量）。

## 1. 拿到工具

```powershell
zig build                      # 产出 zig-out\bin\zcodegen.exe（可拷到任意项目）
zig-out\bin\zcodegen.exe --help
```

也可以直接用构建步骤（等价）：

```powershell
zig build codegen -Dmodel=Entity\Model.xml -Dout=src/entities
zig build codegen -Dmodel=Entity\Model.xml -Dout=src/entities -Dtable=User
zig build codegen -Dmodel=Entity\Model.xml -Dout=src/entities -Dimport=../../root.zig   # 库内自用
zig build codegen -Dmodel=Entity\Model.xml -Ddry-run=1                                  # 只打印
zig build codegen -Dmodel=Entity\Model.xml -Dout=src/entities -Dno-biz=1                 # 不产业务文件
zig build codegen -Dmodel=Entity\Model.xml -Dout=src/entities -Dforce-biz=1              # 强制重写业务文件
```

> PowerShell 里含 `/` 的参数建议整体加引号：`zig build codegen '-Dmodel=Entity/Model.xml' '-Dout=src/entities'`。

反查（数据库 → Model.xml）：

```powershell
zcodegen --reverse "Data Source=..\Data\DG.db;Provider=SQLite" --out Entity/Model.xml
zcodegen --reverse "Provider=MySQL;Server=127.0.0.1;Port=3307;Database=zcode_test;UserID=root" --out Entity/Model.xml
```

## 2. 两个文件：谁覆盖、谁手写

| 文件 | 谁维护 | 重新生成时的行为 |
|---|---|---|
| `{Name}.zig` | 生成器 | **覆盖**。数据契约：字段、`meta`、列名常量、CRUD、缓存入口、必填校验 |
| `{Name}.biz.zig` | **人** | **只在不存在时创建**；已有内容永不覆盖 |
| `mod.zig` | 生成器 | 覆盖。导出全部实体 + `{Name}Biz` |

依赖方向只有一个：`{Name}.biz.zig` → `{Name}.zig`。基础文件**不** import 业务文件，所以不会有循环导入
（单测里直接断言这一点）。

## 3. 接进自己的项目

```zig
// build.zig
const entities = b.createModule(.{ .root_source_file = b.path("src/entities/mod.zig") });
entities.addImport("zcode", zcode);          // zcode = 本库的模块（Pek.ZCode）
your_mod.addImport("entities", entities);
```

```zig
const entities = @import("entities");
const User = entities.User;
const user_biz = entities.UserBiz;           // 业务扩展（可选）

var u = User{};
u.setName("alice");
u.valid();                                   // null = 通过；否则返回第一个为空的非空字符列名
_ = try u.insert(&dal, &s);                  // 自增 ID 回写到 u.Id
u.setName("alice2");
_ = try u.update(&dal, &s);                  // 只写脏列

const got = (try User.findByPk(&dal, &s, u.Id)).?;
```

## 4. 生成物清单（对照 C# `EntityBuilder`）

| 成员 | 说明 |
|---|---|
| `dirty: zcode.entity.DirtyBits` | 脏列位图；setter 置位，同值不置位 |
| 每列的 `getXxx` / `setXxx` | 访问器（`setXxx` 走 `valueEql` 比较后再置脏） |
| `pub const meta` | `EntityMeta`（名称/物理表/字段/主键/自增/累加/长度精度/描述） |
| `pub const indexes` | 索引元数据（与 `Model.xml` 同源） |
| `pub const main_keys` / `identity_index` / `additional_indexes` | 列下标常量 |
| `pub const Field` | 列名常量（替代手写字符串） |
| `pub const max_cache_count` | 模型 `MaxCacheCount`（0 = 不参与整表缓存） |
| `table(dal)` | 表级句柄（`TableRef`） |
| `insert/update/delete/save(dal, s)` | 实例 CRUD |
| `findByKey` / `findByPk`（单整型主键）/ `query` / `count` | 静态查询 |
| `cache(dal)` / `singleCache(dal)` | 两级缓存入口（TTL 取全局 `Setting`） |
| `valid()` | 必填校验（`entity_ext.checkRequired`） |
| `columnValue` / `setColumnValue` | 实体 ↔ 行 的桥（`fromRow` / 写库都靠它） |

**未生成**（有意）：导航属性别名（运行期在 `navigation.zig`）、`DeleteWith/DropWith`（分表由 `shards.zig` 路由，
DDL 走 `Dal.syncSchema`）。

## 5. 自检（改生成器后必须跑）

```powershell
zig build codegen '-Dmodel=examples/demo-model.xml' '-Dout=examples/entities'
zig build gen-check '-Dgen-check=examples/entities' '-Dmodel=examples/demo-model.xml'
```

`gen-check` 会编译生成的实体，并在临时 SQLite 上真建表、增删改查跑一遍。`tools/regression.ps1` 已内置：

- `examples/entities` 生成后**不许有 git 漂移**；
- 三个真实模型（C# 主模型 / C# 测试模型 / Rust Pek.RCode 模型）各自 `codegen` + `gen-check`。

## 6. 口径与坑

- **`-Dimport`**：库内自用（生成物放进本仓 `src/` 下）必须传相对路径，否则 `@import("zcode")` 在自身包里循环依赖。
- **不要手改 `{Name}.zig`**：下次生成即丢。要改结构 → 改 `Model.xml`（或 C# 权威模型后跑 `sync-model.ps1`）再生成。
- **业务文件只增不删**：生成器不会删多余的 `.biz.zig`（表删了要手工清）。
- **中文用编辑工具写**：生成物是 UTF-8 无 BOM，不要用 PowerShell 的 `Get-Content -Raw | WriteAllText` 回写（会按 GBK 解码破坏）。
