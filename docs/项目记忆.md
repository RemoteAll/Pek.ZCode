### 已实现（v0.1.0 第一轮）
- `src/`：types / model / dialect / query / sqlbuild / session / dbtable / dal / entity / codegen（11 个文件）。
- 实体（2026-11-11）：`entity.zig` 契约 = `meta` + `dirty: DirtyBits` + `columnValue/setColumnValue`；
  `update` 只写脏列、无脏列返回 0 不发 SQL；`insert` 跳过自增列并回写 ID；`insert_only`/视图禁写。
- 代码生成：`tools/zcodegen.zig` + `codegen.zig`，命令 `zig build codegen -Dmodel=... -Dout=...`（0.17 无 b.args）。
- 批量写（2026-11-11）：`sqlbuild.insertMulti`（多行 VALUES）、`TableRef.insertBatch`（按 maxStatementParams 分批，≤5000 行/批）、
  `TableRef.deleteByPkBatch`（单主键 IN 分批）、`entity.saveBatch`（新增合并批插 + 已有按脏列更新，返回 inserted/updated/unchanged）。
  批量插入不回写每行自增 ID（与 Rust 一致）。
- 测试：本仓 50 项（单元 45 + 集成 5）。
- 整表缓存（2026-11-11）：`cache.Cache(T)`——首访/TTL 过期同步整表重载（Blocking）、主键 i64 O(1) 命中、
  `ttl_seconds=0` 不过期；`Dal` 维护类型擦除的缓存注册表（`{table_name, ctx, invalidate}`），
  `TableRef.setWriteNotifier` 注入回调，写操作（影响行数>0）自动使该表缓存失效。
  **缓存首次使用时才注册**（init 只做值初始化，否则 `@ptrCast(&self)` 捕获栈临时地址）。
- 绿色版：`examples/green.zig` + `examples/entities/`（生成产物），`zig build green-test` 自检；
  regression 增加「绿色版自检」与「生成产物漂移检查（git diff examples/entities）」。
- 方言 5 族：SQLite、MySQL、SQL Server、PostgreSQL（含金仓/瀚高/海量）、Oracle；
  其它（DuckDB/ClickHouse/TDengine/InfluxDB/HANA/Firebird/DB2/达梦/IRIS/Access/MongoDB）枚举占位但 `error.Unsupported`。
- SQLite 执行驱动（在 zzig）：**动态加载** `sqlite3.dll`（exe 目录 → 当前目录 → PATH）→ `winsqlite3.dll`。
- `Dal.syncSchema` 增量：缺表建表（含索引）、缺列补列、缺索引补索引；幂等（二次同步 0 变更）。
- 测试：本仓 `zig build test` **45 项全通过**（单元 43 + 集成 2）；zzig **51 项全通过**；`tools/regression.ps1` exit 0。

### Zig 0.17 坑（都在代码里规避了，新增代码别踩回去）
- `std.DynLib` **不支持 Windows** → 手写 `LoadLibraryA`/`GetProcAddress`/`FreeLibrary`。
- 已移除：`time.timestamp`/`nanoTimestamp`、`crypto.random`、`fs.cwd`、`selfExeDirPathAlloc`、`Allocator.dupeZ`。
  替代：`GetSystemTimeAsFileTime` / `GetTickCount64` / `GetModuleFileNameA` / 手工补 `\0`。
- `ArenaAllocator` **不能中途复制**（后续分配只更新副本 buffer_list → 泄漏）；先分配完再整体移入返回值。
- `sqlite3_bind_text` 必须 `SQLITE_TRANSIENT`；`SQLITE_STATIC` + 栈缓冲会在 step 时读到失效内存。
- 连接串 `Data Source` 必须复制：`Dal` 生命周期长于调用方临时串。

### 语义要点
- `Nullable` 缺省 false（NOT NULL）；`TableName` 缺省 = `Name`；视图 = `IsView` 或表名以 `#` 开头。
- SQLite：自增列内联 `PRIMARY KEY AUTOINCREMENT`、`String` 列 `COLLATE NOCASE`、`decimal` 为 NUMERIC 亲和度
  （尾随零入库即丢，C# 同样）；`INSERT/UPDATE/DELETE` 未知列报 `error.ColumnNotFound`。
- `Where` IN 空集 → `1 = 0`，NOT IN 空集 → `1 = 1`；分页/取前 N 无显式排序时按主键兜底。

### MySQL 绿色执行驱动（2026-11-11 第三轮）
- **用户原话**：「**MySQL 执行驱动** 不是说了参考Rust有一个绿色版本么？」→ 走 Rust 同款**纯协议**，不加载 libmysqlclient。
- 落在公共库 `zzig.db.mysql`（+ `zzig.db.Row` 各驱动共用），本仓只做接线，不复制实现。
- 支持：握手 v10、`mysql_native_password`、`caching_sha2_password`（**仅 fast auth**）、`COM_QUERY`、
  预处理二进制协议（`COM_STMT_PREPARE/EXECUTE/CLOSE`，按 `Value` 绑定）、`COM_PING/QUIT/INIT_DB`。
- 显式报错不降级：TLS、`caching_sha2` 完整鉴权（明文需 RSA，提示建 `mysql_native_password` 用户）、
  `MULTI_STATEMENTS`、`FOUND_ROWS`（与 Rust 默认能力集一致）、压缩、LOCAL INFILE。
- 接线：`session.Driver = union(enum){sqlite, mysql}`（`init()` 原签名保留）；`Dal.lib: ?sqlite.Lib`；
  `syncSchema` 探测按方言走 `sqlite_master`/`PRAGMA` 与 `information_schema.{tables,statistics,columns}`；
  MySQL 8 的 information_schema 列名是大写 → 按列序号取值。
- 连接串：`Provider=MySQL;Server=;Port=;Database=;Uid=;Pwd=`（也认 Host/User/Username/Password/DataBase）。
- 验证：zzig 单测 9 项 + **回环假服务端端到端 1 项**（真 TCP、服务端重算鉴权摘要逐字节比对）；本仓 `-Dmysql-conn` 真库用例未给则显式 SKIP。
- **真库尚未验证**（本机无 MySQL/无 Docker）：需用户给连接串后 `zig build integration -Dmysql-conn="..."`。
