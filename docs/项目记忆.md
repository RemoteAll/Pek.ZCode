### Zig 0.17 坑（都在代码里规避了，新增代码别踩回去）
- `std.DynLib` **不支持 Windows** → 手写 `LoadLibraryA`/`GetProcAddress`/`FreeLibrary`。
- 已移除：`time.timestamp`/`nanoTimestamp`、`crypto.random`、`fs.cwd`、`selfExeDirPathAlloc`、`Allocator.dupeZ`。
  替代：`GetSystemTimeAsFileTime` / `GetTickCount64` / `GetModuleFileNameA` / 手工补 `\0`。
- `ArenaAllocator` **不能中途复制**（后续分配只更新副本 buffer_list → 泄漏）；先分配完再整体移入返回值。
- `sqlite3_bind_text` 必须 `SQLITE_TRANSIENT`；`SQLITE_STATIC` + 栈缓冲会在 step 时读到失效内存。
- 连接串 `Data Source` 必须复制：`Dal` 生命周期长于调用方临时串。

### 语义要点
- `Nullable` 缺省 false（NOT NULL）；`TableName` 缺省 = `Name`；视图 = `IsView` 或表名以 `#` 开头。
- SQLite：自增列内联 `PRIMARY KEY AUTOINCREMENT`、`String` 列 `COLLATE NOCASE`、`decimal` 为 NUMERIC 亲和度
  （尾随零入库即丢，C# 同样）；`INSERT/UPDATE/DELETE` 未知列报 `error.ColumnNotFound`。
- `Where` IN 空集 → `1 = 0`，NOT IN 空集 → `1 = 1`；分页/取前 N 无显式排序时按主键兜底。

### 真库验证 + 三处实测修正（2026-11-11 第五轮）
- **用户原话**：「那你可以直接下载绿色版本到本地项目并持久保存用于后续测试」「zig的git要过滤」。
- **本地真库**：本机已有免安装 MySQL 8.0.29（`G:\Tools\mysql-portable\mysql-8.0.29-winx64`），
  用 `Pek.ZCode/tools/mysql-local.ps1 -Action setup|start|stop|status|reset` 在项目内起实例：
  端口 3307、数据目录 `.tools\mysql\data-3307`（gitignore，重启仍在）；`--init-file` 幂等建
  `zcode_test` 库 + `root@'%'`/`zcode_native`/`zcode_sha2`（`--initialize-insecure` 只建 root@localhost，
  从 127.0.0.1 走 TCP 会 `ERROR 1130`）。
- **实测修正 1**：BLOB/TEXT 共用类型码，按 `charset == 63` 判二进制（否则 TEXT 读成 Blob：`[blob 12 字节]`）。
- **实测修正 2**：`caching_sha2` 完整鉴权 **用 PKCS#1 v1.5，不是 OAEP**（OAEP 产物 openssl 能解但服务端 1045）；
  载荷 = `RSA((password+'\0') XOR 握手 nonce)`，AuthSwitch 的 nonce 不用于 full auth。
- **实测修正 3**：BIT 线上**大端**（BIT(16) 存 0x0102 → 字节[01 02] → 258）；
  **C# 绿色版小端实现是错的**，Rust 大端正确。
- **另一个坑**：`parseHandshake`/`AuthSwitchRequest` 的插件名借用复用包缓冲 → 下一包被覆盖成乱码，必须拷贝。
- **git 过滤**：两仓 `.gitignore` 用 `.zig-cache*/`、`zig-cache*/`、`zig-out*/` 通配；zzig 补了 `.gitattributes`。

### MySQL LOAD DATA LOCAL INFILE（2026-11-11 第十轮）
- zzig `60924d2`：握手声明 `CLIENT_LOCAL_FILES`（按服务端 capability 取交集）；
  `Conn.loadDataLocal(sql, data)`：COM_QUERY → 服务端 `0xfb` → **客户端流式发数据** → 空包结束 → 读 OK。
  数据不落盘、不需要服务端文件权限。**必须新增 `writeRawPacket`**：`writePacket` 的自动补空包会在
  数据正好 16MB 整数倍时把 LOCAL INFILE **提前截断**。
- 表级 `TableRef.loadDataBatch(session, columns, rows)`（ZCode `e71fd82`）：NULL=`\N`，
  `\\`/`\t`/`\n`/`\r`/`\0` 转义；二进制列报 Unsupported；非 MySQL 方言报 Unsupported 让调用方回落。
- **实测（本机 3307 MySQL 8.0.29，20000 行×5 列，两次取样）**：insertBatch 733~897 ms（36.6~44.9 µs/行）
  vs loadData **194~224 ms（9.7~11.2 µs/行）→ 约 3.8~4.0 倍**；`zig build bench-mysql -Dmysql-conn=…` 可复现。
  原因：多行 INSERT 逐行 SQL 解析，LOCAL INFILE 走行式解析器。
- 坑：① MySQL 8 `local_infile` **默认关闭**，需 `SET GLOBAL local_infile=1`（用例里打不开就显式 SKIP）；
  ② 假服务端必须**声明** `CLIENT_LOCAL_FILES`，否则客户端按交集裁掉、握手后即断；
  ③ **编辑工具「删行末空行」会把 `///` 注释与下一行 `pub fn` 挤成一行**（zbtable/dbtable/README 各踩一次），
  导致「declarations are not allowed between container fields」或命令行被拼进 README —— 改完跑 `zig build` 一眼能发现。
- 测试：本仓 **108/108**（单元 74 + 集成 34）；真库 `-Dmysql-conn` 34/34；zzig 模块 41 + 基础 25；regression PASSED。

### MySQL TLS（2026-11-11 第十一轮，zzig `ef64c1e` / ZCode `ab4e886`）
- `SslMode` 五档（缺省 `Preferred`）：握手发 32 字节 `SSLRequest` → **同一条 TCP 上换裸 TLS** → 在 TLS 上发 HandshakeResponse41。
  连接串认 `SslMode` / `SslCa`，认不出报 `error.InvalidSslMode`。
- **必须供应商化 TLS 客户端** `zzig/src/db/tls_client.zig`（std 副本 + 三处补丁）：MySQL 8 只要配了 `ssl_ca`
  （自动生成证书的默认形态）就在 TLS 1.3 发 `CertificateRequest(0x0d)`，std 直接报 `TlsUnexpectedMessage`。
  补丁：处理 certificate_request、客户端补一条空 Certificate、按协议顺序计入 transcript。std 支持后删掉。
- **踩坑（都是实测）**：
  1. `SSLRequest` 后服务端静默 **10 秒**再回 1043「Bad handshake」= 握手超时（服务端已在等 ClientHello），不是拒绝；
  2. std 报错不带位置 → 复制 Client.zig 逐点 print 才定位到 0x0d；`else => return error.X,`（逗号）按分号替换抓不到；
  3. **TLS 读返回 0 ≠ EOF**：`NewSessionTicket` 被消费时返回 0，按「0=关闭」会得到假 `ConnectionClosed`，必须循环读；
  4. `finalResult()` 是**破坏性**的，取快照要用 `peek()`；
  5. 进 transcript 的是握手消息本身，**不含** TLS 1.3 记录尾部那个内层类型字节；
  6. MySQL 自动生成证书 CN 是随机名 → `VerifyFull` 连 127.0.0.1 必失败，自签场景正确档位是 `VerifyCA`。
- 实测（3307）：Required→`TLS_AES_128_GCM_SHA256`；None→空；VerifyCA 无 CA→`TlsCertificateNotVerified`；
  VerifyCA+SslCa→通过；VerifyFull→`CertificateHostMismatch`。

### MySQL 压缩协议（2026-11-11 第十二轮，zzig `7dc7c0f` / ZCode `42e57ea`）
- 连接串 `Compression=True`（缺省关）：**认证 OK 之后**才切压缩。帧格式 `{3B 压缩长度, 1B 序号, 3B 解压后长度}`，
  解压后长度 0 = 本帧未压缩；<50 字节或压完更大都按未压缩发。
- 两个计数器：内层 `seq` 与 `compress_seq`，发新命令都归零，读响应都从对端包头 +1（**每个 `self.seq = 0;` 处都要同步重置**）。
- 写侧 `wbuf` 攒内层字节后切帧压缩；读侧解压进 `rbuf` 再按 4 字节头切包。
- 坑：① `flate.Compress.init` 断言输出 Writer 缓冲 > 8 字节（空 `Writer.Allocating` 会 panic，用 `initCapacity`）；
  ② `packed` 是 Zig 关键字，不能当变量名；③ 测试载荷别按字节切 UTF-8（会切出半个汉字，MySQL 回 1366）。
- 真库断言：`SHOW STATUS LIKE 'Compression'` 必须 ON；压缩+LOCAL INFILE 1000 行；压缩+TLS 同时生效。
- 测试：本仓 112/112（单元 74 + 集成 38）；zzig 71/71。
