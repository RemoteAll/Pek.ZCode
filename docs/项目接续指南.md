## 1. 项目速览

- 名称：`Pek.ZCode`；目录 `G:\Code\Zig\Pek.ZCode`。
- 定位：**DH.NCode（XCode ORM）的 Zig 实现**——语义与逻辑对齐 C# `G:\Code\Pek.FrameWork\DH.NCode`
  与 Rust `G:\Code\Rust\Pek.RCode`，共用同一份 `Model.xml`、同一个数据库。
  逐项对照（含未实现清单与行为差异）见 `docs/移植对照-NCode.md`．
- 工具链：Zig **0.17.1**（VS Code Zig 扩展托管，`zig version` 实测 0.17.1；0.17.x 均可，0.17.0 已验证同行为）；
  依赖公共库 `G:\Code\Zig\zzig`（path 依赖）：`zzig.xml`（XML DOM）+ 通用件 `zzig.Decimal` / `zzig.DateTime`
  / `zzig.db.Value` / `zzig.db.Row` / `zzig.db.sqlite` / `zzig.db.mysql` / `zzig.crypto.rsa` / `zzig.Buf` / `zzig.File`。
  **本仓不再保留这些通用件的副本**（同一能力只允许一份实现）。
- 当前范围：`Model.xml` 解析、类型/值、5 族方言的 SQL 与 DDL、`Where`/分页、**SQLite + MySQL + PostgreSQL + SQL Server(TDS) 执行驱动**、
  表级 CRUD、对象实体与脏更新、批量写、整表缓存与单对象缓存、事务、连接串与增量结构同步（`Full` 删列删索引 + **改列类型/长度**）、
  **分表分库（含跨库分片与自动建表）/ 读写分离 / 连接池 / 写入拦截器 / 延迟写队列 / 导航属性 / 树形实体 / 备份**、
  **反向工程（库 → `Model.xml`）**、代码生成、**数据库远程服务（`DbService`/`DbClient`，HTTP/1.1 + JSON）**、
  **统计（层级截断 + 累加字段原子累加）**、**数据抽取器（自增 Id / 时间窗 / 分页）**、**窗口函数 SQL 片段**。
  **未做**：Oracle（OCI）执行驱动（无客户端库/无实例，无法验证）；
  SQL Server 的 TLS/集成认证/MARS 未做（服务端要求加密时明确报 `TlsRequired`）。
- 远端：`https://github.com/RemoteAll/Pek.ZCode`（`origin/main`）。

### SQL Server 真库验证：现状与两条后续路径（2026-11-12 实测结论）

`LocalDB` 已装、可用，但**驱动连不上**：它只支持 Windows 认证（`sqlcmd -U sa` → `Login failed for user 'sa'`）且不开 TCP。
TDS 驱动的**命名管道传输已实现**（连接串 `Pipe=` 或 `Server=np:\\.\pipe\...`），缺的只剩认证方式。两条路：

| 路径 | 做法 | 代价 |
|---|---|---|
| **A. 装 SQL Server Express**（推荐） | `SQLEXPR_x64_ENU.exe /Q /ACTION=Install /FEATURES=SQLEngine /INSTANCENAME=ZCODE /SECURITYMODE=SQL /SAPWD=<pwd> /TCPPORT=14333 /SQLSVCACCOUNT="NT AUTHORITY\NETWORK SERVICE" /AGTSVCACCOUNT="NT AUTHORITY\NETWORK SERVICE" /IACCEPTSQLSERVERLICENSETERMS`（需管理员） | 约 250 MB 下载 + 注册服务；装完把真库用例按 `-Dmssql-conn` 接进回归即可 |
| **B. 驱动补 SSPI/NTLM 集成认证** | 在 `zzig/src/db/tds.zig` 实现 Windows 安全协商（`InitializeSecurityContext` + LOGIN7 的 SSPI 包） | 无下载、无系统改动；约 300+ 行，且要在不依赖 TLS 的前提下把 LocalDB 打通 |

**为什么本轮没做 A**：安装会注册 Windows 服务、改动系统，属于需要用户明确同意的动作；本轮用户不在线，
只落地了「零风险部分」（管道传输 + LocalDB 管理脚本 + 文档），没有擅自安装。
